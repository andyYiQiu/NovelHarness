# 语义验收与重复稳定性

该表只用于人工验收，不传入模型，不被生产代码读取。事实和核心性必须按原文判断，不用关键词命中、目标事件数量或同一次模型声明评分。

本系统的验收对象是供下游读取的 `repository`。上游交付先核对目录实际存在、文件与 SQLite 导出收据一致、JSON/JSONL 可解析、人物和地点引用有效、时间节点路径可达、两层 `order` 有效；再按原文核对核心事实、人物关系、认识限定和故事实际顺序。数据库的 `complete` 是内部运行状态，不能替代磁盘交付与语义验收；`partial` 及其 `incomplete.json` 只能按未完成资料处理。具体下游程序的字段适配与任务效果另行联调，不能由本表推断。

每次验收记录：原文位置、预期实际发生、导出事件编号、参与者、事实依据性质、所属节点及事件顺序、缺项或错误。允许不同措辞和合理分组；不允许把不同时间的重要经历压成无法恢复顺序的摘要。

《祝福》的核对锚点（不是固定事件配额）：

| 原文依据 | 应检查的内容 | 历史正式实验的已知反例 |
|---|---|---|
| “她是春天没了丈夫的”；“她诚然是逃出来的” | 初次丧夫、逃出求工及受雇的因果 | 丧夫遗漏；逃出被写成后来证实的行为 |
| “一个抱住她……拖进船去了” | 强迫劫走与主体、婆婆/中人区分 | 写成主动回家并帮忙 |
| “早已许给了……贺老六”；“一头撞在香案角上” | 被迫再婚与反抗，发生者不是讲述者 | 两次记录卫老婆子描述，主体/时间混淆 |
| “断送在伤寒上”；“五脏已经都给吃空了”；“大伯来收屋，又赶她” | 贺老六死亡、阿毛遇难、被赶走及求工的因果 | 多事混成概述，提前写为乞丐，收屋缺项；正式79又把二次返鲁排在丧夫丧子之前 |
| “祭祀时候可用不著她沾手” | 再受雇后的祭祀排斥及实施者 | 基本涉及，但说明混淆原因 |
| “价目是大钱十二千”；“快够一年……已经……捐了门槛” | 请求与实际捐献相隔近一年，不是次日完成 | 请求被写成完成，后续实际完成被删为重复 |
| “冬至的祭祖时节”；“你放著罢，祥林嫂” | 捐后仍被排斥，精神恶化 | 事件保留，前置捐献时间错误 |
| “看现在的情状，可见后来终于实行了” | 解雇和乞讨，保留叙述者推断与路径未知 | 有记录，须保留认识限定 |
| “有没有魂灵”；“死了？”；“昨天夜里，或者就是今天罢” | 临终询问、实际死亡与获知分开 | 询问重复，实际死亡未独立表达；正式79仍以获知死讯替代实际死亡 |

人物核对包括叙述者、鲁四老爷、四婶、祥林嫂、卫老婆子、婆婆、贺老六、阿毛、柳妈、短工等原文出现的参与者；不得以名单作为模型输入或强制输出配额。

时间采用两层：节点顺序唯一；节点内事件可先后、可同时。核对重要因果先后，不要求不同运行生成完全相同的节点名称或编号。只有已确认顺序才用于比较，未知不能当作正确。

格式38额外核对动态资产：初始状态是否确属故事实际起点前，而非叙述开头或最终状态；人物关系方向、适用阶段及结束是否有原文依据；物品所有者、持有者与位置是否被混同；首次获知、传闻、计划是否被误写成实际转移。核对每项delta的basis和来源、事件归属及变化字段，不因填表增加非核心事件。顺序同号的事件共享前态并合并变化，下一节点入口快照应能由上一快照和事件delta重建；没有证据的值保持unknown，明确没有才用none/inactive。人物档案不再包含无时点relation，物品档案、object_ids、state_path及相关引用须可达。结构回放通过不能证明状态的语义真实。

格式39继续核对全体资产：快照不能只包含事件参与者；物品目录有详细状态、事件原文明确持有或损坏，状态却始终unknown，是遗漏，不是合格的未知。首次有据确认状态不等于原文叙述了取得过程。正式94的反例是18件物品初始行全漏、11件无后续delta，其中竹篮/破碗/竹竿的晚期持有与状况有明确原文。验收时从SQLite内部证据对照原文；公开repository已移除所有evidence字段，不能把公开不展示误认为内部不需要依据。

2026-10-20补充字段完整性验收：同时核对空值与非空值中的信息遗漏，不按总体null占比评分。下表只作人工对照，不输入模型或增加逐字段证明协议。正式94的21条事件中20条required_results为空，47个参与者条目中30个original_goal为空；前者有正文已写实际结果的明确遗漏，后者包含被动经历者等合理未知，不能一概要求填满。

| 原文/字段情况 | 应保留的信息 | 不应为减少空值添加的内容 |
|---|---|---|
| 贺老六“年纪轻轻”（原文第129行），age为空 | 年轻，保留卫老婆子转述性质 | 具体年龄或出生年份 |
| 祥林嫂留下试工，第三天定局，月钱五百文（第65行），required_results为空 | 试工后受雇及约定工钱，简记实际结果 | 把所有参与者都写成求工目的，或把预期当完成 |
| 无名劫人者的年龄/性格无交代 | 未知仍为null；行为保存在原有事件与传记 | 用职业、外貌或一次行为编年龄、稳定性格 |
| 地点/背景detail已有文字 | 核对是否保留具体空间、环境、制度内容 | 仅有事件列表就认定详细，或补外部地理/历史知识 |
| 晚期竹篮、破碗、开裂竹竿（第5行） | 对应时点的持有与状况及物品描述 | 因手持推成拥有，或将晚期状态倒填故事起点 |

验收还要比较原有核心因果、两层order、动态回放及未知保留；不能把填字段造成的幻觉、额外普通事件或检查空转算作改进。时间契约固定为空的精确起止、时长、节点间隔不计入提取遗漏。

重复稳定性至少比较同原文、同代码/配置的多次独立输出，分别统计关键事实遗漏、错绑、混合事件、无据内容、时间逆序和完整交付。保存人工对应关系。先要求正确，再比较一致性；不把每次重复同一错误视为稳定达标。没有新实验授权时只维护标准，不发起这些运行。
